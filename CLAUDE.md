# CLAUDE.md

Заметки для Claude Code о том, чего не видно из кода сразу. Общее описание,
настройки и API — в README.

## Язык и порядок работы

- Тексты интерфейса, комментарии, сообщения коммитов и описания PR — на русском.
  Коммиты в стиле `feat: …`, `fix: …`, `docs: …`; тело — что и зачем.
- В `main` напрямую не коммитить: всегда отдельная ветка и PR.
- В каждом PR, который меняет поведение, API или настройки, обновлять README.
- Перед PR прогнать `make vet test lint` и собрать образ
  `docker build -f cmd/todoapp/Dockerfile .` (то же делает CI).

## Архитектура

- Каждая фича в `internal/features/<фича>` разложена по слоям
  `transport/http → service → repository/postgres`. Транспорт только разбирает
  запрос и отдаёт DTO, права и бизнес-правила — в сервисе, SQL — в репозитории.
- Общий код — в `internal/core/*`: домен (`core/domain`), ошибки, логгер, пул БД,
  HTTP-инфраструктура, клиент Telegram, аутентификация.
- Имена пакетов — с префиксом слоя или фичи через подчёркивание: `core_auth`,
  `core_http_response`, `tasks_service`, `notifications_service`,
  `lists_postgres_repository`. Импорты с теми же алиасами.
- Сервис зависит от интерфейсов репозиториев, объявленных у себя в `service.go`;
  в тестах сервисов — фейковые репозитории в памяти, без БД.
- Ошибки оборачиваются `fmt.Errorf("…: %w", err)` с одной из `core_errors`
  (`ErrNotFound`, `ErrInvalidArgument`, `ErrConflict`, `ErrForbidden`, …) — по ней
  `core_http_response` выбирает HTTP-код. Детали 5xx клиенту не уходят.
- `PATCH` — трёхзначная логика через `Nullable` и оптимистичная блокировка:
  клиент присылает `version`, при расхождении — `409`.

## Права доступа

- Доступ к задаче даёт только её список: пользователь владеет списком или
  участвует в нём. Авторство задачи доступа не даёт: вышедший из общего списка
  теряет и свои задачи в нём.
- Чужие задачи и списки отдаются как несуществующие (`404`), не `403`. `403` —
  только участнику, который видит список, но не может им управлять.
- Администратор (`AUTH_ADMIN_TELEGRAM_IDS` и локальный адрес) видит всё.

## Безопасность

- Порт 5051 (`AUTH_LOCAL_ADDR`) — вход без Telegram с правами администратора.
  Никогда не открывать наружу: ни в compose (только `127.0.0.1`), ни в туннеле,
  ни в Caddy, ни в файрволе.
- Токен бота не печатать: ни в логах, ни в ошибках, ни в выводе команд, ни в
  тестах. Он входит в адрес запроса к Bot API — сетевые ошибки проходят через
  `redact` в `core_telegram`.

## База данных и миграции

- Новая миграция — только новой парой файлов: `make migrate-create seq=<имя>`.
  Применённые миграции не редактировать.
- Все объекты — в схеме `todoapp`: в SQL всегда с префиксом `todoapp.`
  (таблицы, индексы в `CREATE INDEX … ON todoapp.…`, ссылки `REFERENCES`).
- На сервере пользователь БД называется `todoapp`, как схема. Поэтому у migrate
  в Makefile стоит `search_path=public`: иначе таблица версий искалась бы в схеме
  `todoapp`, и миграции пошли бы с первой. Не убирать.

## Время

- Даты и сроки считать в часовом поясе пользователя (`User.Location()`), а не
  сервера (сервер работает в UTC).
- Учитывать переход на летнее время: сутки — это не всегда 24 часа. Дни
  сравнивать по календарной дате (`time.Date(…)`), а не делением на 24 часа.
- Задача «на весь день» (`due_all_day`) хранит в `due_at` конец местных суток
  пользователя; показывать у неё только дату.

## Сервер

- Адрес: `https://178-236-248-53.sslip.io` (Caddy + Let's Encrypt, код в
  `/opt/todoapp`). Обновление после мержа: `make server-update` (git pull, копия
  базы, миграции, пересборка).
- Отличия Linux-сервера от Docker Desktop на Mac: на Linux права на смонтированные
  папки проверяются. Контейнер работает от uid `10001`, поэтому `make server-up`
  отдаёт ему `out/logs` (`chown`). Новые монтируемые папки — так же.
